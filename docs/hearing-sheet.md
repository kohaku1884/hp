# ヒアリングシート（卒業制作 Week 11）

> 目的：要件定義書・サイトマップ・WordPress構成設計に必要な情報を、講師（クライアント役）から漏れなく引き出し、整理する。
> 凡例：◎＝必須（これが無いと要件定義書が書けない）／○＝推奨／△＝あれば良い

---

## 0. 進め方のコツ

- 1回の送信で聞くのは **5〜8問**まで。第1弾（基本）→第2弾（深掘り）→第3弾（確認）の3回に分ける
- 「何かありますか？」ではなく **選択肢つき・仮説つき**で聞く（例：「ターゲットは30〜40代の女性と想定していますが、合っていますか？」）
- 講師が答えに詰まったら、**こちらから案を出して承認をもらう**（架空クライアントなので、設定を一緒に作る意識）
- 回答は必ず当日中に **議事録（下記テンプレ）** へ反映し、Chatworkで共有する
- 未確定は「未確定」として残し、期限つきで再確認する

## 1. ヒアリング項目一覧

### A. 事業・会社の基本情報
| 優先 | 質問 | 要件への影響 |
|---|---|---|
| ◎ | 会社（店舗）名、業種、所在地、創業年、従業員規模 | 会社概要ページ・構造化データ |
| ◎ | 提供しているサービス・商品の種類と数 | サービスページ数、CPT化の要否 |
| ◎ | 強み・他社との違い（選ばれる理由） | TOPのキャッチコピー・訴求軸 |
| ○ | 理念・ビジョン・代表メッセージの有無 | 会社概要の構成 |
| ○ | 実績・事例・お客様の声・メディア掲載の有無 | 実績ページ（CPT候補） |
| △ | ロゴ・ブランドカラー・既存の印刷物 | デザイン方針 |

### B. サイトの目的・ゴール
| 優先 | 質問 | 要件への影響 |
|---|---|---|
| ◎ | サイトを作る目的（問い合わせ増・採用・信頼性向上・予約など） | 全体設計の軸 |
| ◎ | 最重要ゴール（CV）は何か（問い合わせ／電話／予約／資料請求） | 導線・CTA・フォーム設計 |
| ◎ | 成果の目標（例：月○件の問い合わせ） | KPI・SEO方針 |
| ○ | 現状の課題（既存サイトがある場合は不満点） | 改善ポイント |
| ○ | 今回やらないこと（スコープ外） | 範囲の明確化 |

### C. ターゲット
| 優先 | 質問 | 要件への影響 |
|---|---|---|
| ◎ | 主なお客様像（年齢・性別・地域・BtoB/BtoC） | デザイン・文章トーン |
| ◎ | お客様が抱えている悩み・サイトを見る動機 | コンテンツ設計 |
| ○ | 閲覧デバイス（スマホ中心かPC中心か） | レスポンシブ優先度 |
| ○ | どう検索して来るか（想定キーワード・指名検索か） | SEO・ブログ設計 |

### D. 競合・参考サイト
| 優先 | 質問 | 要件への影響 |
|---|---|---|
| ○ | 競合として意識している会社・サイト | 差別化・サイトマップ |
| ◎ | 「好き」な参考サイト2〜3件と、その理由 | デザインの方向性 |
| ○ | 「嫌い」「避けたい」イメージ | デザインNG |

### E. コンテンツ・ページ構成
| 優先 | 質問 | 要件への影響 |
|---|---|---|
| ◎ | 載せたいページ（TOP／会社概要／サービス／実績／お知らせ／ブログ／採用／FAQ／お問い合わせ 等） | サイトマップ |
| ◎ | 各ページの原稿・写真・素材は誰が用意するか（ダミーで可か） | Week 12のダミー投入 |
| ○ | 写真素材の有無（撮影済み／フリー素材／イラスト） | デザイン・制作範囲 |
| ○ | 必須で入れたい文言（法的表記・プライバシーポリシー等） | 固定ページ追加 |

### F. 更新・運用（WordPress構成設計に直結）
| 優先 | 質問 | WP設計への写像 |
|---|---|---|
| ◎ | 公開後、更新するのは誰か（ITに詳しいか） | 管理画面の使いやすさ・ACF設計 |
| ◎ | お知らせの更新頻度（月○回） | お知らせ＝CPT or 投稿 |
| ◎ | ブログ・コラムを運用するか／目的は集客か | 投稿＋カテゴリ設計 |
| ◎ | 件数が増えるもの（実績・スタッフ・商品・メニュー等）はあるか | **CPT化の候補** |
| ○ | 更新者が自分で変えたい箇所（TOPのバナー・料金表など） | **ACF化の候補** |
| ○ | 公開日を未来にする予約投稿・非公開の必要性 | 運用ルール |

### G. デザイン
| 優先 | 質問 | 要件への影響 |
|---|---|---|
| ◎ | 目指す印象（信頼感／親しみ／高級感／先進的 など。3語程度） | トンマナ |
| ◎ | ブランドカラー・NG色 | カラー設計 |
| ○ | フォント・写真のテイスト（実写／イラスト／余白多め等） | Figmaデザイン |
| ○ | アニメーション・動画の希望有無 | 実装難易度・表示速度 |

### H. 機能
| 優先 | 質問 | 要件への影響 |
|---|---|---|
| ◎ | お問い合わせフォームの項目・返信方法・通知先 | フォーム設計 |
| ○ | 予約・資料請求・会員機能などの有無 | プラグイン・スコープ |
| ○ | Googleマップ・SNS連携・Instagram埋め込み | 外部連携 |
| △ | 多言語対応・検索機能・ページ内検索 | スコープ |

### I. 技術・環境
| 優先 | 質問 | 要件への影響 |
|---|---|---|
| ○ | ドメイン・サーバーの有無／既存サイトの引っ越し有無 | 公開手順（Week 13） |
| ○ | 既存のアクセス解析（GA4等）・Search Console | SEO・計測 |
| △ | SSL・メール（独自ドメインメール）の有無 | 公開準備 |

### J. スケジュール・体制・予算
| 優先 | 質問 | 要件への影響 |
|---|---|---|
| ◎ | 公開希望日・外せない期限 | スケジュール |
| ◎ | 窓口担当者・確認にかかる日数・承認者 | 進行ルール |
| ○ | 予算感（今回は架空なので「想定規模」でOK） | 機能の取捨選択 |

## 5. AIの使い方（このフェーズ）

- 質問が思いつかない → Claude.ai に「[業種]のサイト制作ヒアリングで聞くべきことを、優先度つきで」
- 講師回答の整理 → 回答をそのまま貼って「上記テンプレの議事録に整形して。未確定事項も洗い出して」
- 回答の矛盾チェック → 「この回答同士で矛盾・不足している点を指摘して」
- 最終判断（優先度・取捨選択）は**自分で**行い、根拠を議事録に残す

## 6. 講義資料からの追加：「絶対聞くべき」項目（書面で合意する）

> 後で揉めやすい項目。**必ずChatworkの文面（書面）で合意を残す**。

| 分類 | 確認事項 |
|---|---|
| 更新運用（CMS化の範囲） | ・どのページを**自分たちで更新したい**か<br>・ブログ／お知らせを誰がどの頻度で更新するか<br>・更新者のPC操作への慣れ（管理画面の作り込みに影響） |
| 素材・著作権 | ・提供される写真・テキストの著作権は誰にあるか<br>・写真は用意できるか。できない場合の対応（撮影／フリー素材／別料金）<br>・ロゴデータの形式（ai / svg / png） |
| 法的要件 | ・フォームで個人情報を扱う → **プライバシーポリシー必須**<br>・業界規制（医療広告ガイドライン、士業の表記ルール等）<br>・商品を売る場合は特商法表記 |
| 修正対応・検収 | ・完成後の修正は**何回まで**含むか<br>・「完成」と判断する基準（検収条件） |
| 支払い・本番公開 | ・着手金／中間払い／完了払いの配分<br>・本番公開・サーバ契約・ドメイン取得は**こちらで代行か、クライアント側か** |

## 7. 5W1H チェック（HP版・漏れ確認用）

| 軸 | 質問 |
|---|---|
| Why | ・リニューアル／新規作成の背景<br>・既存サイトの有無と不満点<br>・一番達成したいこと（問い合わせ／信頼感／採用／集客） |
| Who | ・ターゲットの年齢・性別・属性<br>・競合は何社くらいか、自社の強み・差別化<br>・ターゲットが「サイトで一番知りたいこと」 |
| What | ・必要なページ<br>・**自分たちで更新したいページ**（ブログ／お知らせ／施工事例など）<br>・動的機能（フォーム／予約／検索）<br>・**載せなくていい情報**（スコープを切るため） |
| When | ・公開希望日（絶対か、多少ずれてもOKか）<br>・公開後の更新頻度（運用設計の判断材料） |
| Where | ・ドメイン取得済みか、サーバは決まっているか<br>・既存のメールアドレス・SNSとの連携 |
| How | ・参考サイト3つ<br>・ロゴ／ブランドガイドライン／写真素材の有無<br>・文章は誰が用意するか（こちらで作る場合は別工数）<br>・予算感 |

## 8. クライアントの「曖昧な発言」を具体化する

発言をそのまま受け取らず、下記のように掘り下げる。万能の質問は「**具体例で教えてください**」「**参考サイトはありますか？**」。

| クライアント発言 | 確認すべきこと |
|---|---|
| 「きれいなサイトに」 | どんな「きれい」か？参考サイトを3つ |
| 「信頼感のある感じ」 | 色味・雰囲気の参考、競合との違い |
| 「自分たちで更新したい」 | どのページ？頻度は？操作レベルは？ |
| 「お知らせを載せたい」 | お知らせとブログは分けるか？カテゴリは？ |
| 「スマホ対応」 | どの機種まで？ |
| 「お問い合わせフォーム」 | 何項目？どこにメールが届く？自動返信は？ |
| 「施工事例を載せたい」 | 何件くらい？1件に何の情報（写真／コメント／間取り）？ |

> **フラグ立て**：「施工事例」「お知らせ」など**繰り返し増えるコンテンツ**が出たら、その場で「これは投稿 or CPT」とメモしておく。後のWordPress構成設計の種になる。

## 10. 会話直後のメモ整理 → 議事録として共有

会話直後にメモを整理し、クライアント（講師）にも議事録として送る。

### AI（Claude.ai / Claude Code）に整理させるプロンプト

```
以下のヒアリングメモを議事録として整形してください：

[メモを貼る]

【整理ルール】
- 「決定事項」と「確認事項（後で聞くこと）」を分ける
- 「自分たちで更新したいページ」を明示してまとめる
- 抜け漏れがあれば「追加で聞くべき項目」として末尾に
- ビジネス文書として体裁を整える
```

## 11. ヒアリングを要件に落とす

```

   ↓ 整理・取捨選択

   ↓
```

### スコープを明文化する（最重要）

要件定義書に「**やること**」「**やらないこと**」を必ず書く。HPは機能が膨らみやすいので、ここを切っておくと後が楽。

```markdown
## スコープ

### やること
- ○ページ（TOP / 会社概要 / サービス / ブログ / お知らせ / お問い合わせ）の制作
```

## 12. 仕様変更・追加要望への対応

実案件で「仕様変更がゼロだった案件」はほぼゼロ。卒業制作でも講師が意図的に揺さぶってくる。**発生する前提**で備える。

### 仕様変更の3パターン

| パターン | 例 | 対応 |
|---|---|---|
| 軽微（短時間） | 文言修正・色味調整・1リンク追加 | サービスで対応OK。ただし「次回からは別途」と記録 |
| 中規模（数時間〜半日） | セクション追加・スマホ調整の追加 | 追加見積もりが必要 |
| 大規模（1日以上） | ページ丸ごと追加・予約システム新規 | 別案件として扱う（新規見積もり） |

### 対応フロー（すべて記録する）

```
1. 内容を確認：「○○を追加したい、というご依頼でよろしいですか？」
2. 影響範囲を特定：「この変更は、既存の○○にも影響します」
3. 工数見積もり：「○時間程度かかります」
4. 追加料金・スケジュール影響を提示：「料金は別途○円、公開日が○日延びます」
5. クライアント決定：「進めますか？」
6. 書面で合意：Chatwork で記録
```

### 「追加料金」を切り出すときの言い方

- ✕「あ、それは追加料金です」（突き放した印象）
- ○ 下記のように、**数字で透明性を確保し、決定権はクライアントに渡す**

```
採用ページの追加ですね、確認いたしました。

こちらは当初のスコープには含まれていない内容のため、
新規ページの設計・デザイン・実装で○時間ほどかかる見込みです。

追加料金 ○円（税別）にて対応可能ですが、いかがいたしましょうか。
なお、本件の対応により公開日が○日ほど後ろにずれる可能性がございます。
ご検討よろしくお願いいたします。
```

### 「公開日を早めて」への対処：選択肢を提示する

```
【選択肢A】スコープ縮小：ブログを公開後対応にすることで前倒し可能
【選択肢B】料金追加（特急対応）：通常の30%上乗せで全機能を期日内に
【選択肢C】調整なし：元の公開日でいかがでしょうか
```

→ クライアントが選べる形にする。

### AI に交渉文面を書かせるプロンプト

```
クライアントから「採用ページも追加で」と言われました。
当初スコープ外なので、丁寧に、追加見積もりが必要な旨を伝える返信文を書いてください：

- 当初スコープには含まれていないことを角が立たないように説明
- 工数と追加料金の目安（金額は私が埋めます）
- スケジュールへの影響
- 「対応可能です、ご検討ください」と決定権を渡す

語調はビジネス文書、丁寧だが毅然と。
```

→ AIが叩き台を出してくれる。**金額・工数は自分で判断して埋める。**
